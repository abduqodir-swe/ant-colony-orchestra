# Ant Colony

Пиксельный офис, в котором AI-агенты — муравьи. PM получает задачу, раздаёт её специалистам
(backend, frontend, QA, security, devops и др.), они пишут код в общей рабочей папке, запускают
тесты, а рискованные действия (деплой, прод-БД, ключи, merge) ждут твоего Approve/Deny.

## Запуск

**Только офис (демо, без сервера):** любой статический сервер из корня репозитория.

```bash
python3 -m http.server 4173
```

**С бэкендом** (агенты + SQLite + SSE; он же отдаёт офис):

```bash
cd server
npm install
npm start
```

Открой <http://127.0.0.1:8787> и дай задачу PM в строке под офисом.

Без API-ключей сервер работает в **mock-режиме**: агенты действуют по сценарию, без запросов к
моделям и без затрат, но файлы, тесты и одобрения настоящие. Чтобы включить реальные модели,
положи ключ в `server/.env` (образец — `server/.env.example`):

```bash
ANTHROPIC_API_KEY=...
```

По умолчанию все агенты работают на `anthropic/claude-opus-5-5`. Модель отдельного агента
меняется переменной `ANT_MODEL_<ID>`, например `ANT_MODEL_BACKEND_01=openai/gpt-5.6-sol`
(нужен соответствующий ключ провайдера).

## Как устроено

- `index.html`, `src/` — офис и дашборд (чистый JS). Если `/api/health` отвечает, панели
  переключаются на живые данные, иначе показывают симуляцию.
- `server/src/agents.ts` — PM-супервизор и 12 специалистов, общая папка
  `server/workspace` с инструментами файлов и shell в песочнице ОС (Seatbelt на macOS, bwrap на
  Linux; сеть из песочницы закрыта). Без песочницы каждая shell-команда ждёт одобрения.
- `server/src/tools.ts` — план PM, запуск тестов (`node --test`), рискованные действия с
  `requireApproval`. Деплой, merge, прод-БД и ротация ключей пока **симуляции**: они пишут в
  `server/workspace/.colony/actions.log`.
- `server/src/runtime.ts` — очередь задач, перевод событий агентов в события офиса, одобрения.
  Ожидающее одобрение переживает перезапуск сервера.
- `server/data/colony.db` — журнал событий, запуски и одобрения (SQLite);
  `server/data/agents.db` — память агентов и снимки приостановленных запусков.

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | режим (live/mock), песочница, недостающие ключи |
| GET | `/api/state` | снимок: агенты, план, одобрения, последние события |
| GET | `/api/events` | SSE: снимок при подключении, затем по событию на сообщение |
| POST | `/api/tasks` | `{"text": "..."}` — задача для PM |
| POST | `/api/approvals/:id` | `{"approve": true\|false, "reason"?: "..."}` |
| POST | `/api/runs/:id/cancel` | отменить запуск |

Сервер слушает только `127.0.0.1` и принимает POST только с собственного origin: агенты пишут
файлы и выполняют команды на этой машине, не открывай его в сеть без авторизации.
